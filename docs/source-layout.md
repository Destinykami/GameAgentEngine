# 源码布局与包命名

状态：源码迁移及旧包兼容层移除均已完成并通过离线验证。核对日期：2026-10-23。

## 命名与目录

源码根目录使用 `src/`，正式 Python 包使用 `game_agent`，发行包名为 `game-agent-engine`。`src` 仅组织源码，不作为导入名称。原根目录 `persona_agent/` 的实现全部迁入新包，并按职责分组：

```text
src/
└── game_agent/
    ├── __init__.py       # 按需加载的公共 API
    ├── cognition/        # NPC 编排、反思、规划、对话、反应和自治决策
    ├── memory/           # 记录、门面、排序、维护策略和 SQLite 仓储
    ├── world/            # 世界运行、实体、感知、动作、事件、社交和世界持久化
    ├── models/           # LLM / 向量接口、哈希实现及兼容 HTTP 适配
    └── evaluation/       # 真实模型集成探针，导入时不执行探测
```

示例、离线测试、评测运行器和可视化继续分别放在根目录的 `examples/`、`tests/`、`evals/`、`visualization/`，不混入运行时实现。

反思模块后续已整理为 `cognition/reflection/` 子包，内部区分生成编排、证据写入、冲突处理、窄接口与规则；详见[反思设计](modules/reflection.md)。

## 模块边界

- 原有依赖方向和逻辑不变，本次只调整物理布局、导入、安装与文档。
- 模块内部使用相对导入；跨组件通过明确的子包路径导入，不借助公共根入口绕行。
- 包入口和子包入口按需导出，导入实体、事件、记录或纯策略时不得加载世界运行、SQLite 或真实模型适配。
- `from game_agent import NPC, World, MemoryStore` 是推荐的公共入口；内部实现使用 `game_agent.memory.ranking` 等明确路径。

## 导入契约

用户已要求移除旧包兼容层。仅支持 `game_agent` 及其职责子包，删除 `src/persona_agent/`，发行包中不再包含旧包；`import persona_agent` 及其子模块导入不再支持。删除只验证旧包委托的测试，保留正式入口、按需加载及对象身份检查。

仓库内示例、测试、工具和评测改用正式包路径。已有数据库、JSON 字段、提示词、评分和模拟行为不变；不增加 pickle 兼容承诺。

## 安装与运行

`pyproject.toml` 仅从 src 查找 `game_agent` 正式包，运行时仍无第三方依赖。开发环境可执行 `python -m pip install -e '.[dev]'`，或使用 `uv pip install --python .venv/bin/python -e '.[dev]'`。

pytest 配置包含 `src` 和仓库根路径；测试不再逐文件插入源码搜索路径。示例通过已安装包运行，子进程和仓库外进程同样通过安装找到源码。离线时间线生成器仍需仓库根路径访问测试桩，这一用途与引擎安装分开说明。
