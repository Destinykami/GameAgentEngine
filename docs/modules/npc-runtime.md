# NPC 认知编排与公开边界

状态：编排收尾已实现，通过离线行为、原实现对照及独立安装验证。核对日期：2026-10-23。

## 编排收尾设计

保留正式 `NPC` 作为组件组装与业务调用顺序的唯一编排入口，已将 `cognition/npc.py` 整理为 `cognition/npc/`。不新增旧内部字段代理或兼容层；公开构造参数、方法、类方法及常量的导入方式保持可用。

```text
cognition/npc/
├── __init__.py     # 按需导出 NPC 和既有常量
├── engine.py       # 组件组装、观察/反思/规划/对话/反应的调用顺序
├── state.py        # 单实例时钟、档位、累积、水位、冲突签名及诊断副本
├── observation.py  # 去重先于打分、观察写入、动作描述的近期关系上下文
├── consolidation.py # 按流固化与来源字段继承
├── reactions.py    # NPC 的完整反应 LRU；与 decider 两类缓存分别管理
├── context.py      # 自治、身份及传闻的只读记忆视图
├── persistence.py  # 元数据键、默认值、保存/恢复顺序及文件路径
└── contracts.py    # 各组件需要的模型、记忆及反应端口
```

### 状态与依赖

NPC 独占运行状态和完整反应缓存实例；组件不持有 NPC 或 World，不访问对方私有字段。观察、动作描述、固化及记忆视图通过无状态函数接收当前端口，避免复制 NPC 的模型与存储引用。观察组件返回写入结果，NPC 再按当前档位和共享流累积重要性。固化组件只写情节及来源标记，NPC 再触发共享冲突检查。完整反应缓存通过一次性回调在模型决策之后读取当前档位，保留原写入时机。持久化组件只接收记忆元数据端口、运行状态与 PlanState，不创建 NPC。实际数据库与模型组装由 NPC 工厂负责。

新增 `game_time` 只读属性、`runtime_state()` 独立诊断副本和 `cache_sizes()` 缓存数量；副本中的关系水位也复制，修改诊断不能影响实际运行。示例通过公开时钟读取，测试通过实际观察、反思或数据库元数据准备状态，不迁移成对新私有字段的依赖。World 的调用点不变。

### 必须保留的行为

- `_advance` 所处的各方法入口不变；时钟取 max，但清扫间隔仍用传入 now；每 6 小时清扫一次。清扫失败时游戏时间已推进、清扫水位未推进。`maybe_reflect_self`、共享冲突检查和关系门控本身仍不额外推进时钟。
- 观察先推进时钟、查重；重复只合并，既不打分也不累积。新增先打分/使用预打分、写库，成功后仅非 idle 的共享观察累积。动作描述读取当前关系末 3 条观察，再走 observe，保留两次入口推进。
- 自我反思成功后清零累积，再检查共享冲突；关系反思及冲突都成功后推进观察数水位。共享冲突仍先写签名再调用判定，判定失败保留该签名，不新增失败重试策略。
- 固化按共享流先、关系名称排序；来源为 timestamp >= now-24 的未固化有效观察，保留无上界的原窗口；每流至少 2 条；空白摘要跳过。摘要置信度取最小、importance 取最大，传闻任一为真且 hop 取传闻最大。先写 episode，再标记来源；不增加事务，不回滚先前成功的流。整批成功且有新 episode 才检查共享冲突。
- 反应先取当前计划及信任档位，再查完整缓存；键仍是文本、玩家、0.5 信任档位、计划前 20 字的原拼接。只有 full 写入，已有缓存其他档位仍可命中；LRU 上限 512，命中保留原决策但替换 reason。清理先完整缓存、再 decider 缓存。
- 保存键仍为 npc、game_time、reflected_obs、plan_blocks，按原顺序分别写入；保持原部分写入/异常语义。加载保留阈值覆盖、旧键缺省、水位类型转换、计划恢复、清扫水位设置顺序。tier、累积、冲突签名、缓存、规划中断兜底和消融配置仍不持久化；加载恢复默认配置，不扩大恢复范围。
- 记忆仍存 SQLite，重要性检索仍用绝对 importance/10；模型提示词、亲见/传闻语义、对话回流、隐私边界及 World 调度不变。

### 实施与验收

先保存原 NPC 与确定性时间线，再提取组件并迁移私有状态调用点。复用当前离线测试，补充窄端口、诊断隔离、失败顺序、部分固化与部分保存的契约验证；对照原 NPC 的结果、模型调用、记忆、运行状态和数据库重载。检查新进程依赖隔离、仓库外编辑安装、独立 wheel 安装与文档链接。真实 API、模拟和在线探针不在本轮范围。

未决项：无。改变异常重试、固化事务、时间窗口、反应缓存键或持久化范围均属于行为变更，未纳入本轮。

实施结果：354 个离线测试通过（3.93s），其中新增 14 个组件/失败语义用例和 8 个新进程导入隔离用例。21 组配置共 735 个结果、模型调用、运行状态、记忆、缓存与 SQLite 检查点与原 NPC 相同；6 个旧新数据库双向加载/阈值覆盖检查点相同；12 个编排方法在归一状态引用后 AST 一致；16 步确定性时间线相同。

仓库外编辑安装及独立 wheel 安装均通过公开入口身份、常量按需加载、观察去重、动作描述、反应缓存、固化与 SQLite 保存重载检查。wheel 包含 9 个 NPC 子包文件，不含旧 npc.py 或 persona_agent 包。24 份文档本地链接与 git diff --check 通过。未运行真实模型、真实模拟、在线探针或前端构建。

## 职责与状态所有权

NPC 负责认知组件组装、记忆写入、认知档位、反思触发、缓存及自身保存恢复，并持有规划模块的 PlanState。World 负责空间可见性和生命周期调度，不应读写 NPC 的私有档位、关系反思水位或记忆筛选实现。

组件仍由 NPC 持有；本次不重写 MemoryStore、ReflectionEngine、PlanningEngine、ReactionDecider 或 DialogueManager。两条决策路径继续保留原行为。

后续[反思模块重构](reflection.md)已将生成、写入和冲突职责分开；此处的 NPC 触发阈值、水位、共享冲突签名和调用顺序保持不变。

后续[规划模块重构](planning.md)已统一计划块、中断兜底和当前活动查询的归属。NPC 通过 `plan_state` 替换状态和保存快照；仍在原时机推进时钟、调用规划及响应异常，`plan_blocks` 保存键和中断兜底不持久化的行为保持不变。

后续[对话模块重构](dialogue.md)已分离上下文、单轮生成和独立轮流工具。NPC.speak 仍按原顺序推进时钟、关系反思、生成回复和可选记录来话 / 回复；双人轮流工具不接管这条记忆回流链路，World 的防重复参数保持不变。

后续[事件反应重构](reaction.md)已分离事件评分、关系信任及纯效用策略。NPC.react 仍先查询信任并构造完整缓存键；清理时仍先清完整反应缓存，再清 decider 的评分和信任缓存。组件数量通过 `decider.cache_sizes()` 只读诊断，不暴露可变缓存对象。

## 本次公开接口

| 接口 | 契约 |
|---|---|
| `tier` 只读属性 | 获取认知档位；修改仍经 `set_tier` |
| `maybe_reflect_relationship(entity_id, now)` | 仅 full 且观察数量增加时反思；成功后更新水位，失败保留旧水位并向调用方传播异常 |
| `decision_context(visible_entities)` | 只返回共享流及指定可见实体的关系记忆，保持原插入顺序取末 5 条并拼接 |
| `has_relationship(entity_id)` | 查询当前对象是否存在有效关系记忆，不暴露内部记录 |
| `identity_belief()` | 返回最新有效共享身份信念文本，无记录返回空串 |
| `game_time` 只读属性 | 返回当前单调游戏时钟 |
| `runtime_state()` | 返回包含独立关系水位字典的运行状态副本，不提供修改运行状态的通道 |
| `cache_sizes()` | 返回新的 decisions / events / trust 数量字典，不暴露缓存对象 |

`speak` 与 `World.flush_social` 复用同一个关系反思门控，消除重复实现。门控本身不新增时钟推进；已有调用顺序、异常传播和水位保存键不变。

World 仍决定哪些实体可见、何时注入身份信念和何时调用关系反思；NPC 不获取整个世界对象。信任查询复用已有 `trust_toward`，World 不直接调用 NPC 的 decider。
