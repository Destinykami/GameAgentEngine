# 对话上下文、回复生成与轮流发言

状态：已实现并通过离线行为及安装验证。最后核对日期：2026-10-23。
实现入口：`src/game_agent/cognition/dialogue/`，正式 DialogueManager 导入路径保持可用。
关联设计：[NPC 编排](npc-runtime.md)、[记忆](memory.md)、[社交](social.md)、[动作](actions.md)。

## 1. 职责与目标

对话模块只负责当前说话者可见记忆的检索、原有 LLMContext 组装、单轮回复生成，以及独立的双人轮流发言工具。通过窄接口依赖记忆检索和模型补全文本能力，不依赖 NPC、World、SQLite 或真实模型适配。

NPC 保持时钟推进、关系反思门控和对话观察写入；World 动作层保持感知、发言回流和防重复写入。模型适配保持提示词封装、请求、解析和错误处理；记忆模块保持排序、绝对重要性权重及访问时间更新。

## 2. 重构前实现

一个 73 行的模块包含检索规则、上下文文字、模型调用和双人轮流循环，直接引用完整 LLMClient 与具体 MemoryStore。`NPC.speak` 先推进时钟并尝试关系反思，再生成回复，最后按开关写入对方话语和自己的回复。

双人工具调用 DialogueManager.reply，不调用 NPC.speak；它不新增观察记忆、反思、时钟推进、历史会话或重试。回复上下文不包含本轮完整 transcript，只包含当前话语与检索记忆。

## 3. 已实现设计

```text
cognition/dialogue/
├── __init__.py  # 正式公共入口，按需导出
├── engine.py    # DialogueManager：单轮上下文准备后调用模型
├── context.py   # 查询、可见范围、相关性阈值及原 LLMContext 组装
├── exchange.py  # 两个回复端口轮流发言，不触发 NPC 记忆回流
└── contracts.py # 检索、补全和回复的窄接口
```

上下文准备 → 记忆检索端口 / 共享的 LLMContext 数据类型；生成编排 → 上下文准备 / 模型补全端口；双人循环 → 回复端口。无需独立配置对象、会话数据库或写入组件，不为小模块增加额外状态。

## 4. 状态归属

| 状态 | 所有者 | 生命周期与恢复 |
|---|---|---|
| NPC 名称与人格引用 | DialogueManager | 按原引用持有，不复制人格字典；修改后的值在下次上下文可见 |
| 检索结果与 LLMContext | 当前回复调用 | 不新增缓存或共享可变默认值 |
| 当前话语与 transcript | 双人循环 | 单次调用内；不持久化，不作为额外模型历史注入 |
| last_accessed | 记忆模块 | 检索成功即按原默认更新；模型失败也不回滚 |
| 对话观察与关系反思水位 | NPC / 记忆模块 | 保存恢复机制不变，本次不迁移 |

## 5. 对外契约

- `DialogueManager(llm, store, persona_traits, name)` 与 `reply(player_id, utterance, now, top_k=8)` 保持原参数与返回方式。
- `DialogueManager.two_agent_exchange(...)` 保持静态调用方式；循环提取为 `exchange.two_agent_exchange`，类入口直接引用同一静态函数，不增加委托封装。
- 公共入口导出 DialogueManager、two_agent_exchange 与原 RELEVANCE_FLOOR；不新增 persona_agent 或私有字段兼容层。
- 模型端口只需要 `complete(ctx)`；记忆端口只需要 `retrieve(...)`；轮流端口只需要 `reply(...)`，无继承要求。
- 不改变 `NPC.speak` 和 World talk 的参数、返回或职责。

## 6. 保持的行为

- 查询保持 `话语 (对话者: player_id)`，原话语的空白与内容不做改写。
- 检索候选限定“当前对话者关系面 + 共享流”，保留 `include_player=player_id` 加权、`include_shared=True` 和 `min_relevance=0.1`，不新增类型过滤。
- `mark_accessed` 沿用记忆接口的 True 默认值；不因 remember=False 而关闭真正回忆的访问更新时间。
- LLMContext 的 system 文本、字段、默认 extra、记忆列表引用及当前问题逐字保持；只生成一次 complete 调用，不增加会话历史或空回复替代文本。
- NPC.speak 保持“推进时钟 → 关系反思门控 → reply → 可选记录来话 → 可选记录回复”。先生成再记录，不将本轮新话语提前作为旧证据。
- remember=False 不写对话观察，但仍进行既有反思及检索；record_utterance=False 只抑制来话写入，World 已感知来话时继续以此防重复。空来话 / 空回复依旧各自跳过写入。
- 双人循环保持 A 先回答 opener，B 再回答 A 的回复，共 `rounds * 2` 次；transcript 不包含 opener，仅包含 speaker / utterance；时间不变，空回复也继续传递。
- rounds=0 或负数无发言；bool 和非整数沿用 range 的原行为，不新增校验。中途异常向外传播，不返回部分结果，不继续后续发言，也不回滚已发生的访问更新。
- 检索失败不调用模型；模型失败不触发后续对话观察写入；NPC 观察写入部分失败时保留原先已完成的副作用。原异常处理仍由调用方负责。

## 7. 成本与配置

默认 top_k=8、相关性下限 0.1 不变。单轮一次检索、一次 complete，双人工具按原次数调用 reply。无新增网络请求、向量调用、日志、后台任务、缓存或持久化格式变更。
