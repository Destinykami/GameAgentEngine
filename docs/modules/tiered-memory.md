# 分层记忆与每 NPC 独立原文档案

状态：实施中；存储底层已通过专项离线验证，NPC/对话/检查点待接入。最后核对日期：2026-10-25。
关联设计：[现有记忆](memory.md)、[NPC 编排](npc-runtime.md)、[对话](dialogue.md)、[持久化](persistence.md)、[模型适配](model-adapters.md)。

## 1. 目标与职责边界

面向持续增长的历史保存原文，日常对话优先使用有界的常用记忆，明确回忆时读取重要记忆和原文。每个 NPC 独立拥有主库与档案库，不建立所有 NPC 共用的档案库或跨 NPC 检索入口。

本轮落实分层存储、原文追溯、可补处理的写入、按需对话检索及完整检查点。自动理解任意承诺状态、任意语义历史问题、分布式存储及向量近似索引为后续扩展；不得将设计预期或离线结果描述为真实模型效果。

## 2. 当前实现与已确认变更

当前每 NPC 一个 SQLite 文件；观察先查重/评分，MemoryStore.add 编码失败回滚；对话每轮检索并更新访问时间，无记忆时直接返回固定文本。

2026-10-25 用户确认覆盖相关历史保留规则：

1. 每 NPC 使用独立主库和独立档案库，检查点同时备份和恢复两者。
2. 原文先可靠归档；后续评分、提取、嵌入或生成失败保留原文并允许补处理。档案写入失败明确报错。
3. 本轮启用常用层优先、历史按需查询、候选不自动强化，以及无历史命中时的正常对话。

其余继续保留：SQLite、绝对 importance/10、共享/关系流隔离、自治可见多对象的末 5 条窗口、反思证据范围、信任取证及已确认人格。

## 3. 三层设计

| 层 | 内容 | 使用 |
|---|---|---|
| L1 常用 | 名称/人格、当前关系的近期事件和计划、有效身份/关系概况 | 每轮有界加载；当前对象+共享流；不刷新访问时间 |
| L2 重要 | 高重要性观察、反思、情节及身份信念 | 主库有界候选后按原公式重排；不全量装入上下文 |
| L3 原文 | 实际输入、来话/回复、观察描述及生成的派生记录 | 追加保留；标注来源；按关键词/时间定位并展开原文 |

主库 memory 表和整数证据 ID 保留，新增来源关联表。原文用稳定 UUID，局部序号供分页。每个 NPC 使用 `<name>.db` 和 `<name>.archive.db`；内存 NPC 使用各自独立的两个内存库。档案身份与主库绑定，错误配对或丢失已有档案须报错。

L1 为可重建视图，退出上下文不删除原文；固定人设沿用 NPC 配置，自动摘要不改写人格。L2 重要性不决定 L3 可检索性，普通旧闲聊也可明确查找。

## 4. 数据与状态归属

| 数据 | 所有者 | 生命周期 |
|---|---|---|
| 原文、来源、说话者、关系、游戏时间、会话标识 | ArchiveRepository | 追加；合并/失效/遗忘不改原文；独立备份 |
| 片段及全文索引 | ArchiveRepository | 固定切块及原文偏移；中文字符/双字、英文词预分词；可重建 |
| pending、尝试次数、错误 | 档案处理表 | 与原文同事务创建；成功后标记；失败不删原文 |
| 记忆与来源映射 | MemoryRepository | 与派生插入/合并同事务写入；跨库补处理幂等 |
| 有界向量缓存 | MemoryStore | 按需编码；恢复重建；不把全量原文放入内存 |
| L1/历史路由 | 对话策略 | 每轮临时，按数量/字符预算限制 |

“他说过”“亲眼发生过”“模型推断”分别标识。旧库只导入 legacy_snapshot，不伪造曾被去重丢弃的原句。派生记忆保存原文引用，反思/情节同时保留既有 evidence 链。

## 5. 接口与契约

- 保留 add/all_valid/retrieve/维护接口；低层 retrieve 的显式 mark_accessed 仍可用，新对话不自动刷新。
- 新增原文追加、带关系与时间条件的检索、按 ID 读取与邻文展开、来源追溯、限批补处理及档案备份。
- 原文读取默认仅共享流，查询某关系可包含共享流；精确 ID 读取同样校验范围，不提供跨 NPC 路径。
- 观察可关联已有原文，避免 speak 与 World 上游感知重复归档；真实重复事件仍各存原文。
- remember=False 保持本入口不写；record_utterance=False 表示上游已记录。独立 two_agent_exchange 仍不接管 NPC 观察回流。

## 6. 流程与不变式

写入：原文+pending 提交 → 查重/评分/编码 → 主库插入或合并并关联来源 → 标记完成。主库提交后标记失败，可通过来源映射识别成功，重试不得重复插入或强化。仅成功新增共享记忆推进反思累积。

来话在模型处理前归档，实际回复在生成后归档；生成失败不伪造回复。World 失败仍不提交物理状态/奖励，但已经收到的输入原文保留。

读取：普通对话用 L1；明确回忆/约定/任务问题查询 L2/L3；仅展开有限片段。候选不更新 last_accessed，重复讲述不等于原事件重演。提示词区分关系背景与可提及历史；原文带来源、时间及必要邻文，不将否定/假设/转述当作事实。now 为读取上界。

## 7. 配置、成本与可观测性

L1 默认近期 24 游戏小时、最多 8 条、3000 字符；概况另限条数；历史共用本轮预算。L2 默认重要性阈值 6，包含高阶类型，有界预选后重排且原公式不变。向量缓存默认 1024 条。

档案建立持久全文索引，限制候选及邻文数量；查询不全库嵌入。本轮提供关键词/时间与主库候选语义重排，不宣称任意无词面重叠的档案语义召回或百万条延迟已验证。补处理显式限批，无隐式线程或无限重试。

旧库迁移使用持久分页水位和完成标记；完成后重启不再扫描全部主库。来源关联校验原文的关系和事件时间，避免误将其他关系的原文绑定为当前关系证据。只读审查工具列举 NPC 时须跳过档案库和世界库，不将它们误识别成 NPC 主库。

## 8. 实施与迁移

1. 记忆存储：档案仓储/索引、来源关联、缓存上限、原文检索及旧库快照。
2. NPC：观察/来话/动作归档、来源关联、限批补处理。
3. 对话及模型适配：L1/L2/L3 路由与预算，修改空记忆行为，更新原契约测试。
4. 持久化：新检查点清单包含每 NPC 两个文件，恢复至新目录；兼容旧代，防读取未来档案；缺失/错配不静默补空库。
5. 每模块离线验证、更新文档并单独 Git 提交。
