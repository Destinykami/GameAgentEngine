# 社交观察、传闻路由与反思队列

状态：与实现一致。核对日期：2026-10-23。

## 边界与依赖

- `social_contracts.py` 定义窄认知端口和 `Hearsay` 传输数据，不依赖世界、NPC 实现或存储。
- `social.py` 管理社交待反思队列、第三方听见及传闻转述路由，只依赖该端口和实体模型。
- NPC 负责记忆检索、相关性与传闻跳数上限；通过 `rumor_to_share(query, now)` 返回可转述数据。社交层不读取 MemoryStore 或它的记录字典。
- World 负责提供当前实体 / 认知映射、时钟、半径及开关，保留原社交门面。

## 状态与接口

每个 World 创建独立 SocialRuntime，拥有待处理的 `(认知端口, 关系对象)` 队列。观察成功才入队；`flush` 按原顺序调用 NPC 的关系反思门控，跳过死者，隔离单条失败并在 finally 清空队列。

`World._step_social` 作为兼容诊断视图返回相同队列，生产代码通过 enqueue 写入，不在两处维护状态。队列仍不持久化。

## 保持的传播规则

第三方听见按实体注册顺序处理，仅限范围内存活 NPC，排除说话者与对话者，记录到说话者的关系流，hop=1。转述只选当前话题相关的一条观察，相关性下限 0.15，不刷新访问时间，已达 3 跳不再转述。

保留关于听者及来自听者的回环过滤、文本包装、原关系对象及 hop+1；转述入库和队列登记顺序不变。路由异常原样传播，不能新增吞错或事务语义。

## 验收

复用社交隔离、对话回流、传闻语义、三跳封顶、断环、反思失败清队列和两种 step 刷新测试。检查社交模块独立导入、离线全集和确定性时间线，不调用真实模型。

验证结果：257 个离线测试通过（3.86s）；社交模块独立导入不加载运行器、记忆库或真实模型适配；16 步确定性时间线不变；`git diff --check` 通过。
