# 决策模块与关系记忆边界

状态：与实现一致。核对日期：2026-10-23。

## 已确认的当前行为

- 事件反应由 `NPC.react → ReactionDecider.decide` 按人格、关系和事件价值计算效用。
- 自治行动由 `World.decide_agent → LLMClient.decide_action` 根据上下文选择动作，当前不经过同一个效用门控。
- 对话回复只检索当前对话者的关系面与共享流。
- 自治行动的记忆上下文允许共享流和所有可见实体的关系面，合并后按插入顺序取最后 5 条。多个对象同时可见时，它们的关系记忆可能同时进入同一次行动决策。
- 本轮仅将这段既有筛选封装为 `NPC.decision_context`，没有修改可见性或选择策略。

## 下一步目标

独立自治决策的上下文构建与模型策略，使 World 负责运行时调度与执行，认知模块负责记忆选择，决策模块负责选择动作。保持事件反应与自治行动的区别，不在结构迁移中擅自合并策略。

## 已确认的设计

用户于 2026-10-23 确认保持当前行为，采用 A：共享流 + 全部可见对象的关系面。上下文接口继续接收可见对象集合，不引入先选目标阶段，也不合并事件反应与自治行动。

| 选项 | 输入边界 | 实现影响 |
|---|---|---|
| A：保持当前行为 | 共享流 + 全部可见对象的关系面 | 能在一次决策中比较对不同对象的信任；现有行为兼容 |
| B：严格单对象 | 先确定交互目标，再读取共享流 + 该目标的关系面 | 需要明确目标选择阶段与动作决策阶段，可能改变调用次数与行动结果 |

此确认不改变对话回复的单对象检索范围。自治输入仍有末 5 条记忆窗口，允许多个可见关系面进入窗口，不保证每个对象都有记录入选。

## 模块边界与接口

- 新增 `src/game_agent/cognition/autonomous.py`，仅依赖标准库和实体模型，不导入 World、NPC、记忆库或真实模型适配。
- `DecisionContext` 传递行动者、目标、人格、可见对象、基础感知、历史及物理状态；不包含 World 或注册表。
- `DecisionCognition` 端口仅允许查询对象关系是否存在、信任和最新身份信念；记忆筛选继续由 `NPC.decision_context` 负责。
- `AutonomousDecider.decide` 组装记忆 / 信任 / 身份输入并通过窄模型端口选择行动，不移动实体、不写记忆、不执行动作。
- World 保留 `agent_perception/agent_state/decide_agent` 门面，管理模型注册、可见性、档位门控和每实体异常隔离。未注册模型继续返回原 wait；决策异常继续交给调用方处理。
- 模型方法参数、提示文本、对象顺序、身份开关及历史传递保持兼容。新模块不缓存模型或世界状态。

## 验证安排

选定边界后，以离线模型替身捕获实际输入，验证多对象同场、对象离场及共享流的可见范围；保留现有事件反应消融和失败等待契约。真实模型模拟与在线效果评测不作为当前验收条件。

验证结果：255 个离线测试通过（3.38s）；新增多关系同场 / 对象离场与死亡过滤测试、独立模型输入及身份开关测试，增加自治模块的新进程依赖隔离验证。16 步确定性时间线不变，`git diff --check` 通过。
