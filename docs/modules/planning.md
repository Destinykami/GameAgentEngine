# 规划生成、时间规则与计划状态

状态：已实现并通过离线行为及安装验证。最后核对日期：2026-10-23。
实现入口：`src/game_agent/cognition/planning/`；NPC 持有唯一的 `plan_state`。
关联设计：[NPC 编排](npc-runtime.md)、[记忆](memory.md)、[源码布局](../source-layout.md)。

## 1. 目标与职责边界

规划模块负责日计划与重规划的生成编排、时间边界、计划记忆生命周期及当前计划状态。NPC 负责时钟推进、组件组装和调用时机，通过规划接口取得反应上下文与保存快照。World 继续决定何时跨日规划、何种动作触发重规划；模型适配负责提示词及解析，记忆模块负责 SQLite、排序与向量缓存。

不新增规划策略、分钟级任务、跨日有效期、重试或事务；本次仅拆分职责并保持现有行为。

## 2. 重构前实现

`PlanningEngine` 集中生成、分解、时间归一化、裁剪及写入，直接依赖完整模型接口与具体记忆库。NPC 独立维护 `_plan_blocks` 和 `_current_plan`，查询当前活动、组装规划上下文并解析计划保存字段。部分测试直接访问这些私有字段。

实际实现为日计划顶层块加一次子任务分解；一小时块不分解，重规划不分解。旧注释中的“递归到分钟”不是当前已实现行为。

## 3. 已实现设计

```text
cognition/planning/
├── __init__.py  # 按需导出 PlanningEngine、PlanState
├── engine.py    # 模型生成、分解和写入的顺序编排；保留调用计数
├── rules.py     # 纯时间规则与 PlanBlock 类型
├── memory.py    # 规划上下文读取、计划/中断写入与旧计划失效
├── state.py     # PlanState：块、中断兜底、当前活动及块的保存恢复
└── contracts.py # 两个规划模型方法与记忆读写的窄接口
```

依赖方向：引擎 → 时间规则 / 规划记忆 → 窄接口；计划状态只依赖纯时间类型。组件不获取 NPC、World、SQLite 连接或真实模型适配。NPC 通过唯一的 `plan_state` 对象管理计划，不保留重复私有字段或兼容代理。

## 4. 状态归属与恢复

| 状态 | 所有者 | 生命周期 / 保存方式 |
|---|---|---|
| 当前顶层计划块、中断兜底 | NPC 持有的 PlanState | 每次成功规划后整体替换；日计划清空兜底，重规划保留中断原因 |
| `plan_blocks` 元数据 | 记忆模块存储、PlanState 序列化 | 原键名、数组形状及恢复规则不变 |
| 中断兜底 | PlanState | 与原 `_current_plan` 一样不持久化，重载为空 |
| 日计划 / 重规划计数 | PlanningEngine | 模型生成成功返回后递增；空返回也计数；重载归零 |
| plan / observation 记录及有效性 | 记忆模块 | 原类型、内容、重要性和 SQLite 字段保持不变 |
| 游戏时钟、认知档位、反应缓存 | NPC | 本次不迁移，不改变失效和保存规则 |

保存恢复沿用宽松旧规则：只接收长度为 3 的 list/tuple，前两项为 int/float 后转 int、活动转 str；不额外套用生成时的合法性过滤、排序或去重，原转换异常继续传播。缺失 / 空值回退为空块。

## 5. 对外接口

- `PlanningEngine(llm)`、`make_daily_plan(...)`、`replan_from_now(...)` 的参数及返回 `(ids, blocks)` 保持可用；日计划 ids 只包含顶层块，子任务仍写入记忆。
- `PlanState.replace(blocks, interruption="")`：成功后替换计划；不调用模型或记忆。
- `PlanState.current_activity(now)`：取 `now % 24`，按现有块顺序返回第一个覆盖活动，无匹配为空串。
- `PlanState.context(now, explicit=None)`：显式参数（包括空串）优先，其次当前块，最后中断兜底。
- `PlanState.saved_blocks()`、`PlanState.from_saved(blocks)`：只负责现有计划块快照，不保存中断原因。
- 规划记忆方法负责“前一天活动”叙事与最近 10 条共享观察的上下文；NPC 保持原调用顺序，避免玩家私有观察泄露到共享计划。

移除原 `_save_plan`、`_save_obs`、`_as_hour`、`_valid_block` 及 NPC 的私有计划字段 / 查询方法，调用方直接使用对应组件；不增加兼容层。

## 6. 流程与不变式

- 日计划：模型生成 → 计数 → 收集旧计划 id → 逐块校验、写入与分解 → 全部成功后失效旧计划 → NPC 替换状态。空计划也失效旧计划。
- 重规划：先写中断观察 → 原锚定指令与共享背景拼接 → 模型生成 → 计数 → 时间校验与锚点裁剪 → 收集旧 id → 写入新计划 → 失效旧计划 → NPC 替换状态。
- 不将过程改为整批校验或事务：分解或写入中途失败时，已写入的新记录保留，尚未执行的旧计划失效不提前，NPC 计划状态仍保持旧值。
- 顶层时间只接受 int 或整数值 float，排除 bool、字符串、非整数 float；合法范围 `0 <= start < end <= 24`。维持输入顺序，不排序或合并重叠块。
- 子任务只归一化小时并裁到父块；允许父块外部分裁回，裁空丢弃，不额外套用顶层日界规则。一小时父块不分解，精确回声跳过。
- 重规划锚点保持 `ceil(now % 24 - 1e-9)`；先过滤非法顶层块，再裁掉过去部分，不分解子任务。锚定文本的小时 / 分钟截断方式保持原样。
- 计划内容、`[重规划]` 前缀、中断观察内容及重要性（计划 4、中断观察 5）不变；中断来源实体非空时写入其关系流，否则共享流。
- 模型失败不增加对应计数；分解失败时日计划计数已经增加；重规划模型失败时中断观察已经落库。异常继续由原上层处理。
- 不改变模型提示词、数据库、记忆检索或绝对 `importance / 10` 权重。
