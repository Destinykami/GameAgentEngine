# 回放加载、投影与交互

状态：已实现，通过离线测试、构建及浏览器验收。核对日期：2026-10-23。

## 目标与边界

保留 Phaser 单场景、PlaybackController、Timeline/VisualEvent、已有 UI/角色与素材组织。前端只消费时间线，不决定世界规则或写入 NPC 状态。将 InazumaScene 中素材加载和地图绘制、实体位置/活动投影、事件呈现、指针路由及直播跟随分别提取，Scene 只组装组件与协调生命周期。

目标职责：scenes/assets.ts 负责图片加载/可选素材回退与地图纹理；replay/SnapshotProjection.ts 独占前一地点、索引、巡逻和坐镇光环；replay/EventPresentation.ts 独占对话队列/计时器、气泡、伤害及世界横幅；replay/input.ts 负责原几何命中优先级和拖拽绑定；replay/LivePlayback.ts 独占直播轮询状态、标记和跟随，借回调组装场景及获取播放组件。组件接收 Phaser.Scene 和明确的同级能力，不持有 InazumaScene 或访问其他组件私有字段。

终端/静态网页回放作为另一个只读消费者放到 `game_agent/runners/replay/`：terminal.py 负责文本与暂停节奏，html.py 负责原 HTML 字符串，cli.py 负责 JSON 读取与参数分发。examples/replay.py 只保留原默认路径入口；不保留示例工具函数代理，不给 Python 读取器追加原来没有的校验或容错。

## 保持规则

- URL 参数、默认样本、schema_version=1、旧样本归一化、null 门槛、JSONL 完整行处理与失败策略不变。修正 LiveSource 的坏行/截断处理属于行为变更，本轮不加入。
- 保留所有素材请求与 fallback、绘制顺序、坐标、深度、字体、动画、布局间距、HUD 避让和装饰。单场景时钟不改为多场景。
- 同地点排序、索引大跳转判断、巡逻布局排除条件、退出巡逻先定位后设置死亡、活动中断规则及每帧往返推进顺序不变。
- 对话队列停留时长、连续无新对话保留最后气泡、大跳转清理、伤害/横幅每步清理、成功过滤和系统提示优先级不变。
- 指针仍按直播提示、播放控制、时间轴、面板、详情卡、实体、空白的原顺序命中；move/up/wheel 原处理顺序不变。
- 直播仍 1s 轮询，初次 setup 不重复 addStep，新步 grow/seek 最新，done 隐藏标记并停止定时；初次素材等待期间的原异步顺序与失败语义保持。
- E2E 通过 __REPLAY__ 的正式调试对象访问组件与只读诊断；迁移对白箱旧 Scene 字段的访问，不增加旧私有字段代理。
- 终端/HTML 的文本、血条近似、门槛/null 分支、转义范围、样式、暂停次数、输出路径及空/坏输入异常保持原样。

## 2026-10-25 直播可靠性目标设计
+
+用户确认坏行阻塞并提示，文件变更为另一运行时提示重新加载，不自动混合两轮数据。直播元数据新增可选 run_id，由 TimelineWriter 每次启动分配；历史样本缺少该键仍可读取。播放器同时核对已消费前缀，发现截断或改写后保持当前回放并停止摄入，等待重新加载。
+
+LiveSource 游标仅在完整且可解析行处理成功后推进；坏行修复后原位重试。数据层返回结构化错误状态，LivePlayback 用独立提示文本呈现，不复用已销毁的 loadingText。源读取与轮询/资源初始化均限制单次在途；网络错误允许下一轮恢复，不写入结束状态。结束标记可停止正常轮询；未结束的运行更换必须显式提示。
+
+可选 run_id 属于直播协议，单独提交并回归后端 writer；读取与前端控制修复另行提交。默认静态时间线格式和世界状态不变。

实施验收：10 个前端离线用例、TypeScript/Vite 构建、14 步时间线校验及 102 项浏览器断言通过。新增慢资源加载防重复初始化、关闭后取消、坏行提示/修复恢复、运行替换保留旧回放检查；实际截图确认提示可见且不覆盖主要控制区。历史 31 步样本和正常直播继续通过；未调用真实模型。文件结束后的页面保持普通回放，不继续监视新运行。
