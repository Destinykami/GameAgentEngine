# 世界持久化边界

状态：与实现一致（世界库存储已提取）。核对日期：2026-10-23。

## 职责与依赖

新增 `src/game_agent/world/persistence.py`，由 `WorldStore` 独占 world.db 的连接、锁、表结构迁移、实体编码与元数据读写。它依赖实体模型及标准库，不导入 World、NPC、记忆或模型客户端。

World 仍负责把运行状态组织成快照、恢复注册表与自治模型绑定；每个 NPC 的数据库仍由 NPC / MemoryStore 管理。本阶段不提取 NPC 记忆库，也不改变现有数据库格式。

后续 [NPC 编排收尾](npc-runtime.md) 已将 NPC 的元数据读写与恢复规则提取到 `src/game_agent/cognition/npc/persistence.py`，NPC 工厂继续组装实际记忆库和认知组件。四个原保存键、逐键写入顺序、旧库默认值及部分状态恢复范围保持不变；MemoryStore / MemoryRepository 继续独占记忆库连接和表结构。

## 接口与状态归属

- `WorldSnapshot` 包含实体列表与 JSON 元数据，不持有数据库连接或认知对象。
- `WorldStore(path)` 打开库并兼容旧的五列实体表。
- `write_snapshot(entities, metadata)` 是上下文管理器：进入时替换实体与给定元数据，退出时提交或回滚；上下文内保持锁与世界库事务。
- `read_snapshot()` 是上下文管理器：读取实体和元数据，并在调用方应用恢复结果期间保持锁。
- `close()` 释放世界库连接；World 继续负责关闭 NPC 记忆库。

World 保存时，在世界快照写入后、事务提交前尽力保存各 NPC，沿用原顺序和异常策略。存储层不通过 callback 调用 NPC，也不访问 World 私有状态。

恢复时，World 将读取的实体位置绑定到现有区域对象；缺失区域按已保存坐标重建。NPC 数据目录、自治 NPC 名单、时钟、日计划和固化日锚点沿用原元数据键。模型对象、规则钩子和向量缓存仍由调用方提供或重建。

## 兼容与限制

保留 `World.save/load/close` 的公开签名及内存世界错误。世界库与各 NPC 库仍无跨库原子事务；不增加完整检查点、自动保存配置或钩子序列化等新行为。多进程写入支持不在本次范围内。
