## 职责与依赖

新增 `src/game_agent/world/persistence.py`，由 `WorldStore` 独占 world.db 的连接、锁、表结构迁移、实体编码与元数据读写。它依赖实体模型及标准库，不导入 World、NPC、记忆或模型客户端。

World 仍负责把运行状态组织成快照、恢复注册表与自治模型绑定；每个 NPC 的数据库仍由 NPC / MemoryStore 管理。本阶段不提取 NPC 记忆库，也不改变现有数据库格式。

后续 [NPC 编排收尾](npc-runtime.md) 已将 NPC 的元数据读写与恢复规则提取到 `src/game_agent/cognition/npc/persistence.py`，NPC 工厂继续组装实际记忆库和认知组件。四个原保存键、逐键写入顺序、旧库默认值及部分状态恢复范围保持不变；MemoryStore / MemoryRepository 继续独占记忆库连接和表结构。

## 接口与状态归属

- `WorldSnapshot` 包含实体列表与 JSON 元数据，不持有数据库连接或认知对象。
- `WorldStore(path)` 打开库并兼容旧的五列实体表。
- `write_snapshot(entities, metadata)` 是上下文管理器：进入时替换实体与给定元数据，退出时提交或回滚；上下文内保持锁与世界库事务。
- `read_snapshot()` 是上下文管理器：读取实体和元数据，并在调用方应用恢复结果期间保持锁。
- `close()` 释放世界库连接；World 继续负责关闭 NPC 记忆库。

World 保存时，在世界快照写入后、事务提交前尽力保存各 NPC，沿用原顺序和异常策略。存储层不通过 callback 调用 NPC，也不访问 World 私有状态。

恢复时，World 将读取的实体位置绑定到现有区域对象；缺失区域按已保存坐标重建。NPC 数据目录、自治 NPC 名单、时钟、日计划和固化日锚点沿用原元数据键。模型对象、规则钩子和向量缓存仍由调用方提供或重建。

+用户确认保存失败明确抛错，运行器终止。`World.save()` 将在 NPC 保存失败时抛出带阶段、NPC 名称和原始异常的 `SaveError`，世界库事务回滚。世界库写入或提交失败同样包装并保留原因。已经提交的 NPC 库不宣称被回滚；旧 save/load 仍是实时数据库入口。一致检查点将在独立目录发布，属于另一个接口和提交。

## 一致检查点目标设计（2026-10-25，用户确认）

新增显式 `World.save_checkpoint(root)` 与 `World.from_checkpoint(root, data_dir, llm, embedder=None, agent_llms=None, configure=None)`。调用者在两步之间暂停世界修改；本引擎不保证并发写入快照。检查点为独立代目录，包含 SQLite backup 导出的世界/NPC 库、版本化清单和文件校验值；全部成功后以同目录临时文件原子替换 LATEST 指针。旧代保留。发布前异常不改变旧指针；不会把实时库部分写入当成完整检查点。

恢复只读取 LATEST 明确指定、版本及文件校验通过的一代；不扫描半成品猜测“最新”。复制到新的运行目录（已存在则拒绝覆盖），不打开检查点原库写入。世界和 NPC 时钟、记忆、计划、认知配置/档位/累积/水位、空间过渡水位、社交队列、行为链规则/计数、自治注册及人格一起恢复。每个组件通过其公开状态导出/恢复接口维护自身字段；World 不访问其他组件私有字段。

模型、嵌入实现、动作回调及威胁过滤函数由调用者重新绑定；清单记录必需的效果绑定数量/威胁过滤要求，缺少 configure 或绑定不完整时拒绝恢复。缓存和向量重建；上一帧视觉事件不作为待执行动作重放。不承诺真实模型输出逐字重现。旧 save/load 继续用于实时数据库，旧库不自动伪装为检查点。

失败测试覆盖 NPC/世界导出、清单和发布阶段，以及校验失败、运行目录已存在、缺失运行依赖、备份后实时库继续变化与新进程恢复。此接口不提供检查点自动清理或断电硬件耐久保证。

保存失败修正验收：5 个故障注入用例先在旧代码失败，修正后 436 个离线测试通过。覆盖三种 NPC 保存顺序、世界提交失败和运行器资源释放；一致检查点仍以专项验收为准。
