# 反思生成、证据写入与冲突处理

状态：已实现并通过离线验证。最后核对日期：2026-10-23。
实现入口：`src/game_agent/cognition/reflection/`，正式公共导入路径保持 `game_agent.cognition.reflection`。
关联设计：[记忆](memory.md)、[NPC 编排](npc-runtime.md)、[源码布局](../source-layout.md)。

## 1. 目标与职责边界

反思模块将观察提炼为自我认知、关系判断或身份信念，校验证据、抑制同义重复，并处理新证据对旧信念的矛盾。

NPC 继续负责触发阈值、认知档位、时钟、关系反思水位和共享冲突签名。记忆模块继续负责检索排序、向量缓存、有效性更新与 SQLite。模型适配继续负责提示词、请求、返回解析与端点降级。反思模块不获取 NPC、World 或数据库连接。

## 2. 重构前实现基线

单个 `ReflectionEngine` 同时承担三种生成流程、写入校验、同流语义去重、两种冲突策略和判定缓存。依赖具体 `MemoryStore` 和包含其他推理能力的 `LLMClient`；评测通过私有字段调整证据相关性下限。测试覆盖流隔离、身份生命周期、证据过滤、去重成本、冲突窗口、衰减幂等和降级。

## 3. 已实现设计

```text
cognition/reflection/
├── __init__.py   # 正式公共入口，按需导出 ReflectionEngine 与既有阈值/词表
├── engine.py     # 自我/关系/身份生成编排及冲突入口
├── writing.py    # ReflectionWriter：去重、证据作用域校验、记录写入
├── conflicts.py  # ConflictResolver：策略分派、失效/衰减及判断缓存
├── contracts.py  # 模型与记忆的窄接口，只依赖记忆记录类型
└── policies.py   # 既有阈值和启发式词表，保持取值
```

依赖方向：入口 → 引擎 → 写入组件 / 冲突组件 → 窄接口与纯策略。生成只调用反思相关模型方法，冲突组件只需要 `judge_conflict`；写入组件不调用 LLM。各组件通过记忆公开方法访问状态，不依赖具体仓储。子包及基础接口导入不加载 SQLite、NPC、World 或真实模型适配。

不为了减少重复而合并三种生成流程：它们的取证范围、空问题降级和置信度规则不同。两种冲突策略也保留各自扫描规则。

## 4. 数据与状态归属

| 状态 / 数据 | 所有者 | 生命周期与恢复 |
|---|---|---|
| 触发累积、关系水位、共享冲突签名 | NPC | 保持现有保存恢复方式和更新时间 |
| 问题、候选证据、洞察 | 引擎 | 每次调用临时数据，原异常向调用方传播 |
| 去重嵌入器、阈值 | 写入组件 | 每个引擎独有；复用记忆的向量缓存 |
| `(反思内容, 观察内容)` → 矛盾强度 LRU | 冲突组件 | 每个引擎独有，上限 512；不持久化；失败不缓存 |
| 记忆及置信度 / 有效性 | 记忆模块 | SQLite 契约与字段不变 |

## 5. 对外接口与契约

`game_agent.cognition.reflection.ReflectionEngine` 的构造参数及四个公开方法保持原调用方式：

| 接口 | 作用域和输出 | 副作用 / 降级 |
|---|---|---|
| `reflect_self(store, now, recent_n=100)` | 仅共享观察生成问题和取证；返回新 id | 空问题跳过；初始置信度 0.8 |
| `reflect_relationship(store, player_id, now)` | 单个关系流；返回新 id | 空问题回退到原 NPC 名称问题；置信度 `min(0.95, 0.5 + 0.1 * 原始引用数)` |
| `reflect_identity(store, now, recent_n=50)` | 所有流的反思 + 共享观察作为原料，写入共享 identity | 固定原问题；允许跨流有效证据；与 reflection 分池去重 |
| `check_conflicts(store, player_id, now, shared=False)` | 关系流，或共享 reflection + identity；返回被修改 id | off 不扫描；heuristic_decay 不调用 LLM；其余值保留 full 路径 |

引擎公开 `evidence_types`、`evidence_min_relevance`、`conflict_policy` 供评测配置，构造时仍将证据类型转为 tuple；评测调用方迁移到公开名称。移除原有私有 `_save` 及冲突辅助方法的混合职责，组件测试直接验证 `ReflectionWriter.save` 或 `ConflictResolver.check`，不添加私有方法兼容委托。

窄接口声明 `all_valid`、`retrieve`、`vectors`、`add`、`invalidate`、`update_confidence` 的实际使用子集；只约束能力，不要求继承，不改变 `MemoryStore`。

## 6. 流程与不变式

- 问题过滤只去掉非字符串与空白项，不修改保留问题文本；模型调用顺序、参数、每次洞察请求 `n=3` 保持原样。
- 证据检索使用 `mark_accessed=False`，候选证据不刷新遗忘锚点；检索仍使用绝对重要性权重。
- 写入顺序保持“同流、同类型去重 → 证据校验 → 新记录入库”；先按原始引用数计算关系置信度，不因过滤改变它。即使过滤后无证据，仍按原行为入库。
- 证据校验保留顺序与重复，仅过滤不存在、失效或越界 id；身份信念允许全部有效记忆。去重阈值 0.92，已有向量从记忆缓存取得。
- LLM 冲突仅查时间戳严格更晚的最近 10 条未固化观察 / episode；按时间稳定排序；置信度低于 0.1 跳过。强度 ≥7 失效并停止该信念扫描，≥3 计入衰减。
- 启发式路径保留原词表子串匹配，并扫描全部更晚证据，不套用 LLM 的最近 10 条窗口。两路径的衰减均为 `base_confidence * 0.5 ** 冲突数`，只写下降值。
- 缓存命中更新 LRU 次序，包括值为 0 的命中；模型异常传播且不写缓存。多 NPC 不共享缓存，重启后按原行为重建。
- 本次不改变提示词、数据库、模型解析、NPC 触发、保存恢复或反思行为。

## 7. 配置、成本与可观测性

默认 `evidence_types=("observation",)`、相关性下限 0、冲突策略 full，其余消融参数及未知策略的回退行为保持原状。不新增网络请求、日志副作用、后台任务或持久化缓存。
