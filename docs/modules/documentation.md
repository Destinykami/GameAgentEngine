## 4. 数据与状态归属

`docs/modules/` 维护当前模块契约；`docs/archive/` 维护历史材料；各自状态由文档明确标记。归档不迁移数据库或运行产物，不触及已有未跟踪材料。

## 5. 对外接口与契约

历史文档的仓库相对路径变为 `docs/archive/<原文件名>`，根目录不留同名占位文件；仓库内导航统一更新。仓库外保存的旧路径不会自动重定向，可从项目首页或设计入口进入归档。

## 6. 流程与不变式

先建立本设计和设计索引入口，再迁移与修复链接，最后记录验证结果并提交。除归档标记、链接及导航外，历史内容保持原样；当前有效的设计文档继续留在原位置。

## 7. 配置、成本与可观测性

无新增配置、依赖或模型调用；通过 Git 重命名记录追溯。文件清单、本地链接检查及差异检查作为验收证据。

## 8. 实现与迁移计划

1. 建立设计与索引入口。
2. 迁移 8 份文件、建立归档索引和历史标记、调整文档链接及导航。

4. 回填结果，仅暂存本次文档修改，以文档模块提交到本地 Git。
