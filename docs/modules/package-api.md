# 包入口与依赖加载

状态：与实现一致。核对日期：2026-10-23。

## 问题与目标

即使导入独立实体或事件子模块，Python 也会先执行包的 `__init__.py`。原入口立即导入 NPC、World、记忆库及真实模型适配，导致静态拆分后的模块仍在运行时加载整套框架。

包入口改为按导出名延迟解析。公开名称、`__all__` 顺序、版本、对象身份和星号导入保持兼容；仅在请求某个名称时加载对应实现，并缓存解析后的对象。

## 边界

- 正式入口为 `src/game_agent/__init__.py`，子包入口共用 `_lazy.py` 的按需导出逻辑；按用户要求移除旧 `persona_agent` 导入兼容层。布局详见 [源码设计](../source-layout.md)。
- `__init__.py` 只维护公共导出表，不创建运行对象或发起网络请求。
- 实体直接映射到 `world.entities`，记忆记录直接映射到 `memory.models`，NPC / World 映射到各自运行模块，模型与存储按需加载。
- 保留类型检查时的显式导入和 `dir()` 的公开名称发现。
- 不更改子模块内部依赖，也不新增插件注册机制。

## 验收

在新 Python 进程中分别导入实体、事件和感知模块，确认没有加载 World、NPC、记忆库、真实模型适配或 SQLite。检查星号导出和正式入口对象身份，运行离线全集。真实模型验证不在本阶段范围内。

验证结果：251 个离线测试通过（3.93s），包含 3 个新进程依赖隔离用例及公共导出兼容用例；16 步确定性时间线不变；`git diff --check` 通过。

旧包兼容层移除后：280 个离线测试通过；正式入口与依赖隔离检查保留。编辑安装和独立环境 wheel 安装均可导入 `game_agent`，不再提供 `persona_agent`。
